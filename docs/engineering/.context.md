# Engineering Context for AI Coding Agents

This file provides context for AI coding assistants working on the ABA system.

## Project Overview

**What**: HIPAA-compliant ABA data collection and analysis system for schools  
**Scale**: 100 students, ~100 staff, 1:1 therapy ratio  
**Platforms**: Web app (React/Next.js) + Mobile app (React Native)  
**Key Feature**: Offline-first data collection with automatic sync

## Critical Constraints

1. **HIPAA Compliance**: All PHI must be encrypted, logged, and access-controlled
2. **Offline-First**: RBTs collect data without WiFi - must queue locally and sync later
3. **Performance**: Data entry must be < 100ms latency (critical path)
4. **Data Integrity**: No data loss, conflict resolution for offline sync
5. **Accessibility**: WCAG AA compliance required for all UI

## Key Design Decisions

### Why React Native?
- Single codebase for iOS/Android
- Native API access (camera, voice, haptics)
- Offline-first libraries (WatermelonDB, React Query)

### Why PostgreSQL + TimescaleDB?
- Strong ACID guarantees for PHI
- Time-series optimization for analytics
- Row-level security for multi-tenant isolation

### Why Offline-First Architecture?
- School WiFi is unreliable
- RBTs can't stop working due to connectivity
- Optimistic UI for perceived performance

## State Management

**Tool**: Zustand (lightweight, no boilerplate)

**Stores**:
- `authStore`: User session, permissions
- `studentStore`: Student data, programs
- `sessionStore`: Active data collection session
- `syncStore`: Offline queue, sync status
- `uiStore`: UI state (modals, toasts)

**Pattern**: Keep stores small and focused, use selectors for derived state

## Offline Sync Architecture

```typescript
// 1. Record action locally (immediate UI update)
const recordTrial = async (response) => {
  const trial = { ...data, timestamp: Date.now(), _synced: false };
  await localDB.trials.add(trial); // IndexedDB
  updateUI(trial); // Optimistic update
  
  // 2. Try to sync (may fail if offline)
  try {
    const result = await api.post('/trials', trial);
    await localDB.trials.update(trial.id, { _synced: true, id: result.id });
  } catch (error) {
    // Queue for later sync
    await syncQueue.enqueue({ action: 'CREATE_TRIAL', data: trial });
  }
};

// 3. Background sync worker
const syncWorker = () => {
  if (navigator.onLine && syncQueue.length > 0) {
    const item = syncQueue.peek();
    try {
      await api.post(item.endpoint, item.data);
      syncQueue.dequeue();
    } catch (error) {
      if (error.status === 409) {
        // Conflict: server has newer data
        showConflictResolution(item);
      }
    }
  }
};
```

JWT payload:

## Security Patterns

### Permission Check

```typescript
// Backend middleware
const requirePermission = (permission: Permission) => {
  return (req, res, next) => {
    if (!req.user.permissions.includes(permission)) {
      return res.status(403).json({ error: 'Forbidden' });
    }
    next();
  };
};

app.post('/api/v1/programs', 
  authenticate, 
  requirePermission('create_program'), 
  createProgram
);
```

### Audit Logging

```typescript
// Log all PHI access
const auditLog = async (userId, action, resourceId) => {
  await db.auditLogs.create({
    user_id: userId,
    action: action,
    resource_type: 'student',

```

### Data Encryption

- **At rest**: PostgreSQL encryption, encrypted S3 buckets
- **In transit**: TLS 1.3 only
- **In app**: Sensitive fields encrypted with app-level encryption before storage

## Performance Patterns

### Query Optimization

```typescript
// BAD: N+1 query problem
const students = await db.students.findAll();
for (const student of students) {
  student.programs = await db.programs.findByStudentId(student.id);
}

// GOOD: Use joins
const students = await db.students.findAll({
  include: [{ model: db.programs }]
});
```

### Caching Strategy

```typescript
// Cache student data for 5 minutes
const getStudent = async (id) => {
  const cached = await redis.get(`student:${id}`);
  if (cached) return JSON.parse(cached);
  
  const student = await db.students.findById(id);
  await redis.setex(`student:${id}`, 300, JSON.stringify(student));
  return student;
};

// Invalidate cache on update
const updateStudent = async (id, data) => {
  await db.students.update(id, data);
  await redis.del(`student:${id}`);
};
```

### Component Optimization

```typescript
// Memoize expensive calculations
const sessionStats = useMemo(() => {
```

## Common Gotchas

### 1. Don't Block the Main Thread

```typescript
// BAD: Synchronous heavy operation
const stats = calculateComplexStats(10000DataPoints); // Freezes UI

// GOOD: Use Web Workers or break into chunks
const worker = new Worker('stats-worker.js');
worker.postMessage(dataPoints);
worker.onmessage = (e) => setStats(e.data);
```

### 2. Handle Offline Edge Cases

```typescript
// User goes offline mid-request
api.post('/trials', data).catch((error) => {
  if (error.message === 'Network request failed') {
    syncQueue.enqueue({ endpoint: '/trials', data });
    showToast('Saved offline, will sync later');
  }
});
```

### 3. Timezone Handling

```typescript
// ALWAYS store in UTC, display in user's timezone
const trial = {
  timestamp: new Date().toISOString(), // UTC
};

// Display
const displayTime = new Date(trial.timestamp).toLocaleString(userTimezone);
```

## Implementation Workflow for AI Agents

When implementing a feature:

1. **Start with user story**: `docs/product/user-stories/[persona]-stories.md`
2. **Check screen spec**: `docs/engineering/screen-states/[screen].yaml`
3. **Review component registry**: Reuse existing components
4. **Check traceability matrix**: See what's already done
5. **Implement component**: Follow directory structure
6. **Add tests**: Unit + integration
7. **Update traceability matrix**: Mark as 🟢
8. **Check performance**: Measure with React DevTools Profiler
9. **Verify accessibility**: Run axe-core
